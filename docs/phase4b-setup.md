# Phase 4-B セットアップ手順（招待制への切り替え）

管理者が招待した人だけがアプリを使える形にします。設定は**SQLの実行1回だけ**です。

---

## これまでとの違い

| | これまで | これから |
|---|---|---|
| 利用開始 | `@concept-village.co.jp` のGoogleアカウントなら、URLを開いてログインするだけ | **管理者が招待した人のみ** |
| 権限 | 全員「管理者」 | 招待時に「管理者／メンバー」を選ぶ |

**すでに利用者として登録されている方には影響しません。** 権限もそのままです。

---

## 手順：SQLを実行する

Supabase ダッシュボード → **SQL Editor** → **New query**

`supabase/migrations/0003_invitations.sql` の**中身をすべて**貼り付けて **Run**。

> ⚠️ ファイルのパスではなく、**ファイルの中身**を貼り付けてください。

作成されるもの:

| 種類 | 内容 |
|---|---|
| テーブル | `invitations`（招待の記録） |
| 関数 | `is_app_admin()`（管理者判定） |
| トリガー更新 | 初回ログイン時、**招待がある人だけ**を利用者登録する |

**確認**: `Success. No rows returned` と表示され、Table Editor に `invitations` が増えていればOKです。

Vercel 側の設定変更は不要です（環境変数は Phase 4-A のものをそのまま使います）。

---

## 使い方

### メンバーを招待する

1. **ユーザー管理**（管理者のみボタンが出ます）→ **メンバー招待**
2. メールアドレスと権限を入力 → **招待する**
3. 「招待中（未ログイン）」の一覧に追加されます
4. **本人にアプリのURLをお知らせください**

> **招待メールは自動送信されません。** Googleログインのみの構成のため、Supabaseの
> 招待メール（メール内のリンクでログインする仕組み）とは噛み合いません。
> URLをSlackやメールでお伝えいただく運用になります。
> 一覧の「アプリのURLをコピー」ボタンが使えます。

### 招待された人がすること

アプリのURLを開いて、会社のGoogleアカウントでログインするだけです。
ログインした時点で利用者になり、「招待中」の一覧から消えます。

### 招待を取り消す

「招待中」の一覧の **取り消す** を押します。まだログインしていない人にのみ有効です。

## 権限でできることの違い

| | 管理者 | メンバー |
|---|---|---|
| 見積の作成・編集 | ○ | ○ |
| メンバーの招待 | ○ | ✗ |
| 権限の変更 | ○ | ✗ |

権限の確認は画面だけでなく**サーバー側でも行っています**。ボタンを隠すだけだと、
APIを直接呼ばれた場合に誰でも自分を管理者にできてしまうためです。

## トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| 招待した人が「利用者として登録されていません」と出る | 招待したアドレスとログインに使ったアドレスが違う。「招待中」一覧の表記を確認 |
| 「メンバー招待」ボタンが出ない | ログイン中の方が「メンバー」権限。他の管理者に権限変更を依頼してください |
| 「すでに利用者として登録されています」 | その方はすでに利用可能です。ユーザー管理の一覧に載っています |
| 管理者が誰も居なくなった | 利用者が0人になった場合のみ、最初にログインした人が自動で管理者になります。1人でも残っている場合はSupabaseの Table Editor で `users` の `role` を直接 `admin` に変更してください |
