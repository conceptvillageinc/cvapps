# 議事録機能 仕様案（v1）

スマートフォンで録音した打ち合わせの音声を CV AX KIT に取り込み、文字起こしと議事録（要約・決定事項・ToDo）を自動で作る機能。

---

## 1. 目的と使い方の流れ

1. 打ち合わせをスマホで録音する（アプリ内の録音ボタン、または iPhone のボイスメモなど既存の録音）。
2. CV AX KIT の「議事録」で、クライアント・案件・日付を選んで音声を取り込む。
3. 数分後に、文字起こしと議事録の下書きができる。
4. 内容を直して確定する。決定事項と ToDo が残り、クライアントカルテからも見られる。
5. 必要なら、議事録をメールで関係者へ送る／Google ドキュメントに書き出す。

---

## 2. 画面

### 2-1. 議事録一覧（左メニュー「議事録」）

- 列: 日付、件名、クライアント、案件、状態（処理中／下書き／確定）、ToDo の未完了数、作成者
- 検索: 件名・クライアント・本文（文字起こしの全文も対象）
- ボタン: 「＋ 新しい議事録」

### 2-2. 新しい議事録（スマホ前提の縦1列レイアウト）

1. 基本情報: 件名（自動で「クライアント名 打ち合わせ 9/25」を入れる）、クライアント、案件（任意）、日付、出席者（自由入力。社内メンバーは選択）
2. 音声の入力。2 つの方法:
   - **録音する**: ブラウザの録音機能（MediaRecorder）で録る。一時停止・再開、経過時間、残りの目安を表示。録音中は画面をロックしないよう注意書き（iPhone は画面ロック中に録音が止まることがある）。
   - **音声ファイルを選ぶ**: ボイスメモや Google レコーダーの録音を共有シートからアップロード（m4a / mp3 / wav / webm、最大 2 時間・200MB を目安）。
3. 「取り込んで議事録を作る」を押す → アップロード進捗 → 「処理中」画面（閉じても続く。終わると一覧に「下書き」で出る）。

### 2-3. 議事録の詳細（PC・スマホ両対応）

上から:

- ヘッダー: 件名、日付、クライアント（カルテへのリンク）、案件、出席者、状態、作成者
- **議事録（要約）**: AI が作った下書きを編集できる。項目は固定:
  - 概要（3〜5 行）
  - 決定事項（箇条書き）
  - ToDo（担当・期限・内容。チェックで完了）
  - 次回までの確認事項／保留
  - 補足メモ（手入力）
- **文字起こし**: 発話ごとに時刻付き。検索、該当箇所の音声再生（±10 秒）。誤変換はその場で直せる。
- 音声プレーヤー（元の録音）
- ボタン: 「確定」「メールで送る」「Google ドキュメントに書き出す」「テキストをコピー」「削除」

### 2-4. クライアントカルテとの連携

- カルテの左の一覧に「議事録」タブを追加。選ぶと右に要約・決定事項・ToDo が出る。
- 案件詳細にも、その案件の議事録を一覧表示。

---

## 3. データ

新しいテーブル `meetings`（1 件の打ち合わせ）:

| 列 | 内容 |
|---|---|
| id, created_at, updated_at, created_by | 共通 |
| title, held_at, client_id, client_name, project_id | 基本情報 |
| participants | 出席者（文字列の配列） |
| audio_path, audio_duration_sec, audio_size | 音声（非公開バケット `uploads` に保存） |
| status | uploaded → transcribing → summarizing → draft → finalized（error あり） |
| transcript | 文字起こし。`[{ start, end, speaker, text }]` |
| summary | 議事録。`{ overview, decisions[], todos[{ owner, due, text, done }], open_items[], notes }` |
| error_message | 処理失敗時の理由 |
| retention_until | 音声の保存期限（既定 90 日。過ぎたら音声だけ削除し、文字起こしと議事録は残す） |

- 全員が読める（社内ツールの方針どおり RLS はメンバー全員）。
- ToDo は当面 `summary` の中に持つ。案件の工程（project_tasks）へ「工程にする」ボタンで写せるようにする（v2）。

## 4. 処理の仕組み

```
スマホ ──(音声ファイル)──▶ Supabase Storage（非公開）
                              │
                              ▼
                     /api/meeting-process（Vercel Function、最大 5 分）
                       1. 音声を取り出す
                       2. 文字起こし（外部の音声認識 API）
                       3. 議事録の要約（Claude。既存の /api/llm と同じ経路）
                       4. meetings を更新（status = draft）
                              │
                              ▼
                     画面は 5 秒ごとに状態を確認 → 「下書きができました」
```

- 長い録音（60 分超）は 5 分の制限に収まらないことがあるため、音声を 20 分ごとに分割して順に処理する（v1 では「最大 2 時間」を上限にする）。
- 処理中にブラウザを閉じても続く。失敗したら「もう一度処理する」で再実行できる。

### 4-1. 文字起こしのエンジン（要決定）

| 案 | 長所 | 短所 | 費用の目安（1 時間の音声） |
|---|---|---|---|
| **A. Google Gemini（Files API）** | Google Cloud のプロジェクトが既にある。日本語の精度が高く、話者の区別と要約を一度に頼める。長時間の音声も 1 回で扱える | Google AI Studio の API キーの発行が必要（Workspace の管理者で 1 回） | 約 20〜60 円 |
| B. OpenAI Whisper API | 精度・実績とも安定 | OpenAI のアカウントと支払い設定が別に必要。話者の区別はできない。1 ファイル 25MB 制限のため分割が必須 | 約 55 円 |
| C. Google Cloud Speech-to-Text v2 | Google 純正。話者の区別あり | 設定項目が多い（バケットの用意など）。費用が高め | 約 150〜250 円 |

**おすすめは A**。理由は、追加のアカウントが要らない、話者の区別ができる、長い音声を分割せずに済む、費用が最も安い、の 4 点。要約は現在の Claude の経路をそのまま使い、「決定事項・ToDo・保留」の型に沿って出す。

### 4-2. 要約の指示（案）

- 日本語のビジネス議事録。話し言葉を整えつつ、固有名詞・金額・日付・数量はそのまま残す。
- 決定事項と「検討中」を混ぜない。担当・期限が発言に出ていれば ToDo に入れ、出ていなければ空欄にする。
- 見積・印刷に関わる数字（部数・サイズ・納期・予算）は「補足メモ」に必ず拾う。

## 5. スマホからの使い勝手

- **ホーム画面に追加（PWA）**: マニフェストとアイコンを用意し、iPhone／Android のホーム画面から全画面で開けるようにする。ログインは今の Google ログインのまま。
- **録音の現実的な運用**: iPhone はブラウザの録音が画面ロックで止まることがあるため、**確実なのは「ボイスメモで録音 → 共有 → CV AX KIT にアップロード」**。アプリ内録音は短い打ち合わせや補助用と位置づける。
- 通信量: 60 分の m4a は約 30〜60MB。Wi-Fi 推奨の注意書きを出す。アップロードは途中で切れても再開できるようにする（v2）。

---

## 6. セキュリティと保存期間

- 音声・文字起こし・議事録はいずれも社内メンバーのみ閲覧。音声は非公開バケットに置き、署名付き URL（短時間有効）で再生。
- 音声認識の API キーは Vercel の環境変数（サーバー側）に置き、ブラウザには出さない。
- 音声の保存期間は既定 90 日（設定で変更可）。期限後は音声だけ削除し、文字起こしと議事録は残す。
- 録音の際は相手に「議事録のために録音します」と伝える運用ルールを FAQ に載せる。

---

## 7. 段階分け

| 段階 | 内容 | 目安 |
|---|---|---|
| **v1** | 音声ファイルのアップロード → 文字起こし → 議事録の下書き → 編集・確定。一覧・詳細。カルテの「議事録」タブ。PWA（ホーム画面に追加） | 2〜3 日 |
| v2 | アプリ内録音（一時停止・再開）、アップロードの再開、ToDo を案件の工程へ写す、メール送付、Google ドキュメント書き出し | 2 日 |
| v3 | 議事録から見積の下書きを起こす（部数・サイズ・納期を印刷仕様に反映）、全文検索の強化、話者名の学習 | 相談 |

---

## 8. 決めていただきたいこと

1. 文字起こしのエンジン: **A（Gemini）でよいか**。よければ Google AI Studio で API キーを 1 つ発行してもらい、Vercel の環境変数に入れる（手順は実装時にご案内）。
2. 音声の保存期間の既定: **90 日**でよいか。
3. v1 の録音方法: **「ファイルを選ぶ」だけで始めて、アプリ内録音は v2**でよいか。
4. 議事録の項目: 概要／決定事項／ToDo／保留／補足メモ の 5 つでよいか。足したい項目があれば。
5. 閲覧範囲: 全メンバーが全議事録を見られる（今の他のデータと同じ）でよいか。
