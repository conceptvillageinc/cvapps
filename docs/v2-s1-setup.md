# v2 S1: 案件（projects）の導入手順

見積・納品書・請求書の親になる「案件」を追加します。
freee販売からエクスポートした案件（794件）も取り込めます。

所要時間はおよそ15分です。①②④は Supabase の SQL Editor に貼って実行するだけです。

---

## ① テーブルを作る

Supabase → **SQL Editor** → **New query** →
`supabase/migrations/0004_projects.sql` の**中身をすべて**貼り付けて **Run**。

これで次が行われます（何度実行しても壊れません）。

- `projects` テーブルの作成（案件番号 `P-YYMM-連番` を自動採番）
- `estimates.project_id` の追加（見積と案件の紐付け）
- **既存の見積から案件を自動生成**して紐付け（見積番号 `CV-2607-001` → 案件番号 `P-2607-001`）
- クライアントに「請求書の送付方法」「定期売上あり」の列を追加
- 受注確度の選択肢を `A / C / A（定期売上） / 要注意（A）`、
  フェーズの選択肢を `引き合い / 着手中 / 未着手 / 受注済` に更新（freee販売と同じ）
- 期首の月 = 10月 を設定に追加（システム設定画面で変更可）

実行後、アプリを開き直すとサイドバーに **案件一覧** が出ます。

---

## ② freee販売の案件を取り込む（任意）

freee販売の案件（794件）を案件一覧に入れます。**やることは「用意されたSQLを貼って実行する」だけ**です。

### 2-1. 取込用SQLを受け取る

取込用のSQL（`seed_freee_projects.sql`）と突合結果（`seed_freee_projects-review.json`）は、
**freeeのCSVからすでに生成してチャットでお渡ししています。** 2-2 は飛ばして 2-3 に進んでください。

### 2-2. （将来、取り込み直すとき）SQLを作り直す

freeeから改めてエクスポートして取り込み直したくなったときの手順です。初回は不要です。

- **いちばん簡単な方法**: freeeからエクスポートしたCSVをチャットで送ってください。
  同じようにSQLを生成してお渡しします。
- **ご自身で作る場合**: Node.js（無料のプログラム実行環境）が入ったPCで、次のコマンドを実行します。

  ```bash
  node scripts/import-freee-projects.mjs <freeeのCSV> supabase/seed_freee_projects.sql --chunk 100
  ```

  `--chunk 100` で案件100件ごとにファイルが分かれます（SQL Editor のサイズ制限対策）。

  CSVは freee販売 → 案件 → エクスポート で、**「顧客名称」列が含まれる形式**を使います。
  クライアントマスタとの突合を細かくしたい場合は、Base44移行時のクライアントJSON
  （`clients_all.json`）を `--clients <ファイル>` で渡します。無くても動きます（名前の完全一致だけで突合）。

  できあがる2つのファイルは取引情報を含むため**コミットしません**（`.gitignore` 済み）。

  | ファイル | 内容 |
  |---|---|
  | `supabase/seed_freee_projects_1.sql` … | SQL Editor に貼って実行するもの（番号順） |
  | `supabase/seed_freee_projects-review.json` | 突合の結果・要確認事項 |

### 2-3. 実行する

Supabase の SQL Editor は大きなクエリを受け付けないため（「Query is too large」エラー）、
取込SQLは **`seed_freee_projects_1.sql` 〜 `_8.sql` の8ファイルに分割**してあります。

1. SQL Editor → **New query**
2. `seed_freee_projects_1.sql` をテキストエディタで開き、中身をすべてコピーして貼り付け → **Run**
3. 同じタブの中身を消して `_2.sql` を貼り付け → Run。以降 `_8.sql` まで**番号順に**繰り返す

各ファイルの Run は数秒で終わります。結果欄に「Success. No rows returned」と出れば成功です。

案件番号は登録日順に `P-2410-001` から振られます。
**同じSQLを2回実行しても二重登録にはなりません**（同じ案件は上書き、番号は最初のまま）。

## ③ 取込後に確認するもの

`-review.json` を開くと、次が載っています。

| 項目 | 意味 | 対応 |
|---|---|---|
| `clients.partial` | 名前が少し違うが同じ相手とみなしたもの（例: 「○○委員会」と「○○委員会 委員長 △△」） | 違っていればクライアント一覧で案件のクライアントを直す |
| `clients.similar` | 似た既存名があるが、部署違いの可能性があるため**別クライアントとして作成**したもの（例: 「福島県農林水産部農業振興課」と「福島県 農林水産部」） | 同じ相手なら、クライアント一覧で片方を削除し、案件のクライアントを付け替える |
| `clients.created` | マスタに無かったため新規作成したクライアント | 住所・担当者などを補う |
| `notes` | 顧客名なしの行など | 社内の経費行（「【仕入（振込）】支払い分」など）は案件として不要なら削除 |
| `grossProfitMismatch` | freee の「粗利(実績)」が「受注合計 − 発注合計」と合わない行 | アプリでは受注合計 − 発注合計 で計算します。freee の値は案件詳細の「freee販売の元データ」で見られます |

取り込んだ案件はすべて **状態 = 進行中** です。案件一覧は既定で「今期・進行中」だけを
表示するので、過去の案件は期の選択で見られます。終わった案件は詳細画面で「完了」に変えてください。

## ④ 定期売上の毎月自動生成

`supabase/migrations/0005_recurring_projects.sql` の中身をすべて SQL Editor に貼って **Run**。

これで **案件一覧 → 定期売上** の画面が使えます。

1. 「ひな形を登録」で、毎月請求する案件（クライアント・案件名・月額・開始月）を登録
2. 以後、**毎月1日の朝9時**に、その月の案件が自動で1件ずつ作られます（案件名に「（2026年10月分）」が付きます）
3. 登録したばかりで今月分をすぐ作りたいときは、同じ画面の「この月の案件を生成」を押します
   （すでに作成済みの月は二重になりません）
4. 終わる契約は「終了月」を入れるか、状態を「停止中」にします

freee販売から取り込んだ過去の定期案件（受注確度「A（定期売上）」の32件）はそのまま案件として入っています。
続いている契約は、ひな形として登録し直してください（開始月は来月以降にすると重複しません）。

### 自動生成に必要な設定（Vercel・1回だけ）

Vercel → cvapps → **Settings → Environments → Production** → **Add Environment Variable**

| Key | Type | 値 |
|---|---|---|
| `CRON_SECRET` | **Secret** | 長いランダムな文字列（パスワード生成ツールで32文字以上） |

登録後、**Deployments → 最新の「⋯」→ Redeploy**。
この値は Vercel が毎月1日にアプリを呼ぶときの合言葉です。未設定のままだと自動生成は動きません
（手動の「この月の案件を生成」は動きます）。

## 変わった動き

| 画面 | 変更 |
|---|---|
| 新規見積作成 | 最初に**案件を選ぶ**（または「新規案件を作成」）。クライアント名・件名・希望納期は案件から引き継がれます |
| 見積詳細 | 受注確度・フェーズは**案件の属性**になり、変更するとすぐ案件に保存されます。案件へのリンクがヘッダーに出ます |
| 見積一覧 | 受注確度・フェーズは案件の値を表示。クライアント名の下に案件番号が出ます |
| 案件一覧 → 定期売上 | 定期売上のひな形を登録すると、毎月1日に案件が自動生成されます |
| クライアント一覧 | 「請求書送付」列（freee送付／郵送／個別メール／持参）と「定期」チェック |
| システム設定 | 「会計期」（期首の月）を追加 |

案件に紐付いていない古い見積は、これまでどおり見積側の受注確度・フェーズを使います。
