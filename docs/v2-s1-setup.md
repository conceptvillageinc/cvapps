# v2 S1: 案件（projects）の導入手順

見積・納品書・請求書の親になる「案件」を追加します。
freee販売からエクスポートした案件（794件）も取り込めます。

所要時間はおよそ15分です。すべて Supabase の SQL Editor で行います。

---

## ① テーブルを作る

Supabase → **SQL Editor** → **New query** →
`supabase/migrations/0004_projects.sql` の**中身をすべて**貼り付けて **Run**。

これで次が行われます（何度実行しても壊れません）。

- `projects` テーブルの作成（案件番号 `P-YYMM-連番` を自動採番）
- `estimates.project_id` の追加（見積と案件の紐付け）
- **既存の見積から案件を自動生成**して紐付け（見積番号 `CV-2607-001` → 案件番号 `P-2607-001`）
- クライアントに「請求書の送付方法」「定期売上あり」の列を追加
- 受注確度の選択肢を `A / C / A（定期売上） / 要注意（A）`、
  フェーズの選択肢を `引き合い / 着手中 / 未着手 / 受注済` に更新（freee販売と同じ）
- 期首の月 = 10月 を設定に追加（システム設定画面で変更可）

実行後、アプリを開き直すとサイドバーに **案件一覧** が出ます。

---

## ② freee販売の案件を取り込む（任意）

### 2-1. freee販売からエクスポート

freee販売 → **案件** → 一覧の右上 **エクスポート**（CSV）。
**「顧客名称」列が含まれる形式**を使ってください（列が無いと取込スクリプトが止まります）。

### 2-2. 取込用SQLを生成する

手元のPCで（Node.js が必要です）:

```bash
node scripts/import-freee-projects.mjs <freeeのCSV> supabase/seed_freee_projects.sql
```

クライアントマスタとの突合を細かくしたい場合は、Base44移行時のクライアントJSON
（`clients_all.json`）を `--clients` で渡します。無くても動きます（名前の完全一致だけで突合）。

```bash
node scripts/import-freee-projects.mjs <freeeのCSV> supabase/seed_freee_projects.sql --clients <clients_all.json>
```

実行すると2つのファイルができます。**どちらも取引情報を含むためコミットしません**（`.gitignore` 済み）。

| ファイル | 内容 |
|---|---|
| `supabase/seed_freee_projects.sql` | SQL Editor に貼って実行するもの |
| `supabase/seed_freee_projects-review.json` | 突合の結果・要確認事項 |

画面には要点が出ます。例:

```
案件: 794件 → supabase/seed_freee_projects.sql
クライアント: 完全一致 746行 / 部分一致 2社 / 新規作成 27社（うち似た既存名あり 4）/ 顧客名なし 2行
案件名の接頭辞を除去: 699件
受注確度が空: 15 / フェーズが空: 7
粗利(実績)が freee の値と一致しない: 168件（元の値は legacy_data に保持）
```

### 2-3. 実行する

SQL Editor に `supabase/seed_freee_projects.sql` の中身をすべて貼り付けて **Run**。
案件番号は登録日順に `P-2410-001` から振られます。

**同じCSVを2回実行しても二重登録にはなりません**（同じ案件は上書き、番号は最初のまま）。
freee側でデータを直してから再エクスポート → 再実行、という使い方ができます。

## ③ 取込後に確認するもの

`-review.json` を開くと、次が載っています。

| 項目 | 意味 | 対応 |
|---|---|---|
| `clients.partial` | 名前が少し違うが同じ相手とみなしたもの（例: 「○○委員会」と「○○委員会 委員長 △△」） | 違っていればクライアント一覧で案件のクライアントを直す |
| `clients.similar` | 似た既存名があるが、部署違いの可能性があるため**別クライアントとして作成**したもの（例: 「福島県農林水産部農業振興課」と「福島県 農林水産部」） | 同じ相手なら、クライアント一覧で片方を削除し、案件のクライアントを付け替える |
| `clients.created` | マスタに無かったため新規作成したクライアント | 住所・担当者などを補う |
| `notes` | 顧客名なしの行など | 社内の経費行（「【仕入（振込）】支払い分」など）は案件として不要なら削除 |
| `grossProfitMismatch` | freee の「粗利(実績)」が「受注合計 − 発注合計」と合わない行 | アプリでは受注合計 − 発注合計 で計算します。freee の値は案件詳細の「freee販売の元データ」で見られます |

取り込んだ案件はすべて **状態 = 進行中** です。案件一覧は既定で「今期・進行中」だけを
表示するので、過去の案件は期の選択で見られます。終わった案件は詳細画面で「完了」に変えてください。

## 変わった動き

| 画面 | 変更 |
|---|---|
| 新規見積作成 | 最初に**案件を選ぶ**（または「新規案件を作成」）。クライアント名・件名・希望納期は案件から引き継がれます |
| 見積詳細 | 受注確度・フェーズは**案件の属性**になり、変更するとすぐ案件に保存されます。案件へのリンクがヘッダーに出ます |
| 見積一覧 | 受注確度・フェーズは案件の値を表示。クライアント名の下に案件番号が出ます |
| クライアント一覧 | 「請求書送付」列（freee送付／郵送／個別メール／持参）と「定期」チェック |
| システム設定 | 「会計期」（期首の月）を追加 |

案件に紐付いていない古い見積は、これまでどおり見積側の受注確度・フェーズを使います。
